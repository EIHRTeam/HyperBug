# 快速入门

[文档首页](../index.md) · [问题](issues.md) · [账号](accounts.md)

HyperBug 是面向公众反馈的问题跟踪平台。读取公开反馈不需要 Git 仓库或代码托管账号。本手册描述本地验证的候选版本；它已准备但未发布，后端与发布门禁仍开放。

## 找到项目

打开团队分享的项目链接，或在 **Overview** 输入完整项目 ID。本候选版本没有公开项目目录/搜索 API。私有项目需要适当身份与成员权限；被拒绝或不可用页面不会泄露内容。归档项目保留可读历史，但拒绝变更。

打开项目的问题列表，用词语或文档中的过滤器搜索并翻页；URL 保留查询与页状态，支持分享及前进/后退。Minimum 仅搜索标题，Standard 搜索标题与正文；不索引评论。实例页面报告当前配置及不可用能力。

## 提交与讨论

1. 先阅读已有反馈。需要参与时通过 **Account → Sign in** 登录；凭据输入与授权同意均在授权服务完成。
2. 选择 **New issue**，选模板或 Issue Form，填写清楚的标题及必填字段，提交前预览。上传文件可能需要处理/扫描后才能使用；上传本身不代表放行。
3. 只提交一次。结果不确定时重试完全相同的提交，使回执可以协调而不产生重复。表单/修订变更后，先审阅再尝试不同内容。
4. 跟随问题详情链接，在权限允许时评论或回应，用时间线分页/永久链接重访讨论。工作人员按角色标记、指派、更改类型/里程碑及关闭/重开。

草稿与应用令牌只保留在页面内存中。导航、刷新、过期、退出及权限变化可能清空草稿。离开前安全保留自己的文字；公开反馈中不得包含凭据或不必要的隐私信息。刷新后需要再次顶层登录，可复用授权服务独立的第一方会话。

## 了解当前可用范围

公众反馈、表单、安全 Markdown、附件、搜索、分诊、审计浏览、公共 API 与插件基础已通过记录范围内的本地验证。托管后端验收、生产扫描器/代理/提供方验证仍独立进行。关联、保存视图、订阅、通知、批量/导入导出及具体集成属于后续模块；AI 与实时协作暂缓。

上传/冲突恢复见[问题指南](issues.md)，权限/通行密钥见[账号](accounts.md)，工作人员操作见[项目管理](project-management.md)，安全诊断见[故障排查](troubleshooting.md)。[发布说明](releases.md)列明准备但未发布的结果及已知限制。
