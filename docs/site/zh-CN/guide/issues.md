# 查找、提交和讨论问题

[文档首页](../index.md)

产品工作流程已在 Node/PostgreSQL 和两个 Workers 配置档通过本地浏览器验证。线上后端验收和发布就绪状态仍由各自的关卡决定。

## 查找反馈

打开团队分享的项目链接，或在概览页输入完整的项目 ID。实例会检查私有项目的访问权限。搜索和分页状态保存在网址中，因此可以分享链接，也可以通过浏览器前进、后退恢复状态。目前仅支持按创建时间从新到旧排序。

搜索支持普通词语、带引号的短语，以及 `state:open`、`label:UUID`、`type:UUID`、`milestone:UUID`、`author:me` 和 `assignee:me` 等筛选条件。请将 UUID 替换为实际标识符；使用“me”需要登录。项目摘要中列出了标签、类型和里程碑。搜索最多 512 个字符，结果窗口也有上限；达到上限时，请缩小搜索范围。Minimum 实例只搜索标题，Standard 搜索标题和正文，均不搜索评论。

## 提交问题

登录后选择 **New issue**，再选择 Markdown 模板或 Issue Form。填写明确的标题以及所有必填字段。表单支持单行文本、多行文本、下拉选项、复选框和上传字段；必须选中每个必选的复选框。**Preview current content** 会请求实例预览当前草稿，不会发布内容；预览与评论共用请求额度。

草稿仅保存在当前页面的内存中。导航、刷新、退出登录、会话过期或权限变化都会清除草稿。离开页面前，请复制需要保留的内容，并谨慎处理私密信息。如果表单版本变化，请加载当前表单并重新检查每个答案，应用不会自动映射旧答案。

如果无法确定提交是否成功，请保持内容不变后重试。提交回执可防止“请求已保存但响应丢失”造成重复记录。修改内容会开始另一次提交。

## 上传文件和阅读内容

上传需要运维人员配置直接上传目标。选择文件后上传，并按需使用进度、取消和重试功能。文件可能需要处理、扫描并放行后才能使用；字节上传成功并不代表文件安全或可用。提交必填的上传答案前，请检查处理状态。已过期的上传需要重新预留，配额和文件类型限制仍然有效。

内容使用实例统一策略生成的安全表示渲染。服务器会移除原始 HTML、脚本和危险链接。外部图片链接默认不会主动加载；只有选择显示并打开链接后，才会访问外部主机。已放行的附件通过单独配置的媒体源下载，并重新检查当前权限。危险格式作为文件下载，不会在应用中执行。只有已放行且不超过 8 MiB 的 PNG、JPEG、GIF 或 WebP 图片可以在明确操作后预览。

## 讨论和跟踪进展

问题链接包含稳定的问题标识符及其项目内编号。评论和事件共用分页时间线，每次只渲染一页，最多 20 条记录。使用时间线分页链接和评论永久链接可重新查看较早的讨论，浏览器前进、后退也会保留分页状态。

已登录的参与者可以发表评论、添加或移除自己的表情反馈，并在策略允许时编辑或删除自己的评论。维护者可以查看原始编辑历史并执行内容审核。隐藏、涂抹和删除的内容会显示相应的不可用说明。已关闭的问题保留历史，已归档的项目为只读。

## 从错误中恢复

只要停留在当前页面，网络故障不会清除内存中的草稿。发生冲突说明资源已变化：请加载最新版本、对照修改，再决定如何重试。身份失效或权限变化会清除私有缓存和草稿，请使用适当的身份重新登录。敏感的工作人员操作需要近期经过验证的通行密钥登录，仅重复密码登录无法满足要求。

参阅[账号与权限](accounts.md)、[项目管理](project-management.md)以及[内容策略](https://github.com/EIHRTeam/HyperBug/blob/main/docs/MARKDOWN-POLICY.md)。
