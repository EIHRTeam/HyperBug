# 查找、提交和讨论问题

[文档首页](../index.md)

**目标：** 查找已有反馈，提交有用的问题报告，并跟进讨论。

待补充：涵盖项目范围、搜索、筛选、排序、分页、可分享链接和无效搜索；模块 08 验收后再补充搜索语法。

## 提交反馈

待补充：编写模板选择、表单必填项、明确的标题、复现信息、预期与实际结果、预览和提交确认的操作说明。

后端现在可接收有界的 GitHub Issue Forms YAML，保存不可变的表单和模板版本，并提供员工管理 API。创建问题时，启用的表单会生成确定性的 Markdown，并保留结构化答案。旧版草稿必须重新加载表单；已提交成功的请求使用相同幂等键和请求内容重试时，即使表单后来变更，也会返回原问题。模板和启用的表单遵循项目可见性；查看指定版本或已停用的历史需要维护者权限。表单上传答案必须提供匹配的草稿标识，且文件必须由提交者拥有，已经完成校验、放行并绑定当前策略的清洁扫描结果。附件与问题在同一原子操作中关联，每次上传只能被消费一次。实际扫描器验收仍待完成。产品操作界面和浏览器流程验证仍待完成。详见[格式与 API 规范](https://github.com/EIHRTeam/HyperBug/blob/main/docs/ISSUE-FORMS.md)。

## 编写内容与添加附件

已验证的后端策略（模块 07；产品界面仍待实现）：内容支持标题、强调、代码、列表、任务复选框、表格和链接。服务端清理原始 HTML，并移除脚本、事件处理属性、SVG/MathML 及不安全的 URL。正文最多允许 32,768 个 Unicode 码点，同时受 API 字节限制；过深的嵌套或复杂格式会被拒绝。外部图片以不会自动加载的引用表示，供未来的点击加载控件使用。附件引用不授予下载权限。可选的后端上传意图现已预留配额，并为低于配置分片阈值的文件签发短时有效的直接 PUT 凭据。较大的预留使用分片会话创建与恢复、分片上传凭据、回执以及完成或终止操作。终止后仍保留配额，直到物理清理完成；结果不确定的会话创建可能需要运维人员核对。手动调用后台校验可以保留不可变的最终文件内容，但文件仍处于未扫描和隔离状态；自动处理和授权下载交付仍待实现。表单附件关联已经实现，必须通过当前清洁扫描结果与放行状态检查。扫描钩子现已要求在放行前完整校验不可变文件内容、执行隔离并记录结果；尚未配置或验收实际扫描器，合成测试结果不能证明恶意软件检测能力。问题和评论列表返回已存储的纯文本预览，获准访问的详情及可见时间线评论包含安全元素树。此处不声称完成产品浏览器操作验证或部署验收。
