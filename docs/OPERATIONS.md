Owner: Module 13. Date: 2026-10-19. This package is prepared and unpublished. G1 is Not passed, Module 10 Blocked, global G2 Not passed. This runbook does not grant staging or production access. Commands target explicit operator-owned fixtures unless a later rollout is separately authorized. Reader instructions have synchronized English/Chinese counterparts under `docs/site/`.

## Artifact and installation boundary

Use Node 24.21.0/pnpm 11.26.0 and the frozen lockfile. `corepack pnpm build` produces `dist/node/index.mjs`, Workers Standard/Minimum/ingress graphs and `apps/web/dist`. The Node artifact retains external dependencies: retain the frozen workspace/install alongside it. Private source maps are diagnostic artifacts, not public static files. Never ship `.local`, private mounts, tests or root user drafts in a public bundle.

`deploy/node/public-policy.example.json`, `deploy/node/README.md`, the two existing Wrangler configurations and `deploy/cloudflare/README.md` are the packaging entry points. `node tooling/check-deployment.ts node deploy/node/public-policy.example.json` checks public policy offline. The same tool accepts `cloudflare`; it rejects secret/unknown fields. Startup parsers remain authoritative. Offline success says nothing about current keys, actual bindings, primary reachability, HTTPS, storage identity, scanner isolation or paid profile compatibility.

Provision operator material offline with `node tooling/provision-operator-files.ts /absolute/new/private/directory`. This command creates secret files, so use a private parent and secret-manager ingestion, never command substitution, shell tracing or Git. Its public references identify independently generated 256-bit material; files are not activated automatically. Node source mounts require absolute owned regular no-symlink files, mode 0400/0600. Worker Secrets carry the equivalent content. Set ingress from `ingress.txt` without whitespace on both Workers. Bootstrap's Worker binding is `HYPERBUG_BOOTSTRAP_ENROLLMENT`; Node reads `HYPERBUG_BOOTSTRAP_FILE`.

Registry provisioning/rotation is an **internal trusted operator integration**, not a public API or shipped maintenance HTTP endpoint. Obtain `createPostgresKeyRegistry(primaryPool)` or `createD1KeyRegistry(env.DB)` inside the trusted runtime; import `activateOperatorKeys` from `tooling/operator-registry.ts` with the generated public reference list. It calls the existing audited generation-fenced `registry.mutate` once per key. Inspect current state first; an ambiguous failure requires inspection, never blind retry. A partial activation is observable and resumable; the function refuses existing purposes rather than replacing them. No SQL deletion or fake lifecycle is an installation shortcut. The PostgreSQL CLI form requires explicit `HYPERBUG_MIGRATION_DATABASE_URL` and an absolute public-reference file: `node tooling/operator-registry.ts /absolute/private/key-references.json`. Cloudflare's operator integration must run with a real D1 binding in a private runtime; this package does not add a public maintenance Worker.

After migrations/registry/secret prerequisites, enroll the first Staff through `POST /auth/bootstrap/enroll`, from the authorization origin, using the one-time operator code and the existing handle/password request schema. Keep the code/password out of logs and ordinary scripts. Standard then signs in; Minimum's bootstrap session permits registering a passkey. Register `hyperbug-web` with the exact callback/scope. Use a fresh user-verified passkey ceremony for instance administration, generate recovery codes once and store them offline. Project administrator is not instance administrator. Remove the bootstrap secret mount after enrollment. An existing installation must never be reinitialized as a fresh one.

Recovery codes redeem once and revoke prior sessions/tokens. Suspension/activation are audited administrative actions. There is no forced password setter or instance-role management API in the current release. For lost last-administrator access, an operator-channel enrollment re-arm can work only when its store preconditions permit it; do not delete Staff/history to force enrollment. If no code/passkey/eligible operator recovery remains, stop and escalate to the identity owner. This limitation must be part of the release decision.

## Upgrade, application rollback and schema recovery

1. Record source/artifact/config hashes, current migration prefix and supported provider versions. Drain incoming writes and all dispatchers before a consistency capture. Retain existing assets for open browser sessions. Freeze native plugin execution/settings during capture.
2. Pin key versions using `begin-backup`, then capture database, all referenced immutable and staging blob identities, public configuration and separate recoverable secret versions. Finish capture with `finish-backup`. Release a backup pin only after retention and confirmed destruction of **all** copies. Emergency revocation remains possible while capture is active.
3. Verify prior-schema data against pending constraints. Run the forward migration history with the migration owner. PostgreSQL tooling verifies immutable checksums and serializes runners; failed statements/history roll back together. D1 uses its reviewed implicit batches/deferral. Never rewrite an applied migration or disable integrity triggers.
4. For a compatible additive change, migrate first, keep the prior compatible application serving while validating, then replace backend/worker artifacts. For incompatible changes, stop old writers and use the explicitly reviewed maintenance sequence. Search-mode changes require stopping the old dispatcher and bounded rebuilding; mixed modes can invalidate readiness.
5. Configure/release frontend independently with matching config and generated CSP/headers, after API/client compatibility and exact CORS checks. Preview frontend must point to an explicitly isolated staging backend; production is never the default preview fallback.
6. Stop on failed readiness, integrity, key, required audit, auth or smoke checks. Roll back **application artifacts/config** only if compatible with the current schema; this does not reverse migrations. Reconcile pending effects and test a fresh privileged ceremony before reopening traffic.
7. For an irreversible data change, use a reviewed forward fix or restore the coordinated recovery point into isolation. Compare database schema/history/counts/FKs, aggregate timelines/outbox, blob digest/size/type, encryption reads, retained key references and current revocations before switching traffic. Explicitly account for writes after capture and prevent replay to real recipients.

For PostgreSQL, use installed PostgreSQL 18 `pg_dump --format=custom --file=<private-archive> <database>` and `pg_restore --exit-on-error --no-owner --no-privileges --dbname=<isolated-database> <private-archive>` with private environment connection settings. A database dump excludes cluster roles/tablespaces: retain the operator's role/grant manifest separately; inspect any `pg_dumpall --globals-only` output as secret material. For D1 use installed Wrangler export/execute against the explicit selected DB and environment, never the local placeholder remotely. Apply exports to a fresh isolated database, not piecemeal to active aggregates. See Module 13 evidence for commands actually exercised and measured fixture recovery times; no production SLO is promised.

## Planned rotation and compromise

Preprovision a full replacement ring containing current, readable previous and required retained versions; atomically replace the Node file or Worker secret before activating the new registry reference. Use `registry.mutate` with expected generation and unique audit/request UUIDs; the registry prevents unsafe removal, concurrent capture rotation and stale changes. Migrate credential digests and rewrap encrypted protected records under expected record revisions. Verify old/new ciphertext access, then retire only unreferenced versions. Blind-index lookups cap at three readable versions; migrate before adding another. Abuse-key rotation must preserve every live counter/lockout version and its longest live window.

On compromise, revoke immediately through the audited registry, isolate affected credentials/consumers and verify denial on the next request. Do not keep a compromised key readable for convenience. Retain quarantined material only as required for forensic/backup handling; reconcile revocations with any restored older database before serving it. Revocation cannot erase leaked plaintext. Record affected IDs and safe codes, never key material or ciphertext copies in incident notes.

## Background recovery and operator visibility

Use the trusted `replayFailedTask` service with fresh operator authorization, principal/request identity and the exact validated reference. Verify current source, project/principal permissions, plugin registry/settings and provider readiness. The reset and `async.replayed` event commit atomically. Pending reconciliation is automatic; never mark a source delivered manually or mutate raw attempt counters. At-least-once delivery can duplicate an external effect without downstream idempotency.

Rebuild search with the existing sensitive `reindexSearch` application service and returned cursor. Standard pages cap at 25, Minimum 10. Search remains `SEARCH_INDEX_INCOMPLETE` until the selected projection mode is complete. No read performs a fallback scan; no public maintenance endpoint is supplied. Existing scheduled cleanup respects current eligibility, leases, history and physical object absence; failures retain quota/tombstones. Do not clean an active attachment or invent an audit-history deletion command.

Start with structured `component: async` summaries (counts, oldest age, outcome), safe HTTP request IDs/statuses and database operator queries in `deploy/operator-queries.sql`. Avoid payloads, signed URLs, headers and raw provider errors. Production Cloudflare head sampling is 0.1, so diagnostics are incomplete; durable required audit is complete. Free Workers Logs has only three days and no Logpush; inspect bounded retained logs and primary backlog within that window. Provider analytics are delayed/sample-based and are not billing attribution.

Alert proposals are **operator triggers, not established SLOs**: any authorization/key/audit failure, overdue lease with growing backlog across two applicable phase intervals, terminal failure count growth, repeated retry/error increase, or quota usage reaching the allocated budget. Minimum dispatch/job phases recur every 25 minutes; do not treat a five-minute absence as a failure. Saturated counts (1001) are lower bounds. Inspect provider CPU with exact native method/path/status/label attribution and stop harness traffic on >10 ms, missing/ambiguous CPU or a matched failure. Unknown-origin traffic stays outside harness quantiles but consumes account budget.

A queue/provider outage leaves the canonical transaction/outbox durable; restore the dependency and let bounded reconciliation run. Key/auth/CAPTCHA/primary outages deny dependent operations. Search outage leaves direct authorized Issue reads available. Storage/scanner failure must leave attachments quarantined and accounting retained. Never disable authorization, rate limits, TLS verification or required audit to restore availability.
