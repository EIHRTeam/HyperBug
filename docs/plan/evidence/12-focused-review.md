## Security boundaries reviewed

- **Authentication and ADR 0016:** the fixed authorization-origin asset calls only existing same-origin passkey options/verify paths, uses native WebAuthn and fixed error copy, includes required CAPTCHA on final login, and returns to the already-validated authorization request by reload. No bearer, PKCE verifier, password, arbitrary URL or client-supplied code enters the asset. Registration remains explicit and authenticated. Password-only sensitive administration remains denied; native virtual-authenticator registration/login and real PKCE exchange supply assurance 2 in the local browser. Existing CAPTCHA/replay/ceremony and OAuth boundaries are rerun on workerd/D1 and Node/PostgreSQL. No normative security baseline is weakened.
- **Authorization pages and CSP:** exact self script/connect permission is conditional on configured passkeys. CAPTCHA retains its exact provider origin. Validated callback origins remain form-action destinations only; no inline/eval code, wildcard, reflected script source or relaxed callback rule is added. Unsupported pages stay script-free. The fixed JS resource has JavaScript content type, nosniff and no-store. Page tests check escaping, callback/provider separation and unsupported controls.
- **Preview and audit:** closed bounded schemas feed the central content pipeline and existing permission resolver. Preview requires a visible project and authenticated `issue:create`, shares authoritative comment-work admission and adds no persistence or publication. Immutable Issue Form versions/answers are checked server-side. Audit uses the existing project-bound cursor/service and fresh authorization facts; its DTO omits metadata/request IDs. HTTP tests cover anonymous/private/forbidden, invalid fields/cursors/bounds and cross-project cursor rejection. Composition uses the same port semantics on both adapters.
- **Browser state and content:** tokens remain private memory fields; requests omit cookies and reject redirects. 401/403/expiry/identity changes cancel pending work and discard caches/private drafts. Query keys include origin/identity epoch; draft callbacks retain their original revision. Explicit reload now applies fetched snapshots without depending on batched observer renders. The renderer transports the canonical safe tree and supported policy version, with no Markdown parser, second sanitizer, raw HTML sink or automatic external image request. The actual 20-body corpus and nine API rejections run through all local browser profiles.
- **Upload/media:** capability PUT destinations must match configured exact origins, exclude SPA/API/auth origins and reject credentials/fragments/disallowed headers. Storage receives no API Authorization/Cookie header. Capability renewal is bounded to one retry. Direct/multipart progress/resume/cancel and quota/type/expiry states use accepted APIs; actual immutable verification and ClamAV scanning precede release. Downloads use fixed isolated paths, authorization, no-store, omitted credentials, no referrer, rejected redirects, stream/size/time limits and epoch cancellation. Only explicit released PNG/JPEG/GIF/WebP previews use blob images; active media remains attachment/octet-stream/nosniff with sandbox CSP. Browser dangerous-file and byte-exact raster/download tests pass at the separately recorded local provider scopes.
- **Plugins and administration:** real APIs authorize every command; confirmation/recent assurance is retained. Secret reads expose presence only, never values/default secrets. Write-only inputs clear on success and drafts disappear across privilege loss. Native plugin trust and build-time CSP requirements are explicit; enabling a plugin does not load remote runtime JavaScript. No later-module screen, persistence migration or new production dependency is introduced.

The review found and corrected false revision-baseline reloads, missing task-checkbox names, ordinary attachment links bypassing download controls, expired transfer capability recovery and unclear scan/error states. No unresolved security finding was identified within this focused scope. Existing production scanner/provider and hosted/backend acceptance limitations remain explicit in the upload and master records.

## Performance boundaries reviewed

Product queries are independent and deduplicated by Query; search cancels/debounces and rejects stale results, does not trigger automatic retry/refocus loops and has a bounded cache lifetime. Timeline pages replace one 20-row DOM window, including a fixture with 1,000 stored comments. Opening a comment fetches its optional reactions/details/history only as requested; no full-history prefetch or virtualized hidden DOM is added. Management, triage, audit, create and plugin resources remain lazy chunks, with the build graph recorded separately.

Isolated collection uses integrity-verified standalone web-vitals 6.2.3 attribution instrumentation outside production dependencies. It records standard session-window CLS and INP, cold list/detail document LCP and feature-detected Chromium soft-navigation metrics for authenticated create/admin. Unsupported APIs remain a measurement gap rather than a product dependency. Early source attribution found title/loading/discussion replacements causing large startup shifts; heading/status/overview space is now reserved using ordinary CSS minimum sizes, without clipping or hiding content. Final profile measurements, request counts, long tasks, timing limits and large-discussion results belong to the separate performance evidence. No field percentile, hardware coverage, hosted latency or SLO follows from these lab samples.
