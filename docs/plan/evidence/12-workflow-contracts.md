# Module 12 workflow contract decisions

Date: 2026-10-18. User scope: complete Module 12; explicit audit-browsing resume. G1 remains Not passed. No hosted traffic or later module acceptance is included.

The product UI consumes existing operations first. Project selection takes an explicit project UUID (no directory endpoint exists). Stable issue links include the immutable issue UUID and its visible project-local number; the API remains authoritative if the displayed number is stale. Search exposes only its accepted newest-created sort. Timeline pages replace one bounded 20-row window, retaining cursor/permalink state in URLs; no virtualized or content-visibility rendering is introduced without profiling.

Two necessary backend prerequisites are bounded additions to existing policy, to be verified before their product controls are enabled:

- `POST /api/v1/projects/:projectId/content/preview`: authenticated visible-project member with `issue:create` permission; closed body `{body}` bounded by the canonical 32,768 code point / 131,072 byte Markdown policy, returning `{bodyTree,contentPolicyVersion}`. Uses the same server pipeline as committed content. Previews share the existing `comment-create` authoritative principal/project content-work budget (120/2,400 requests per hour, one-day counter retention). Explicit preview requests consume that budget alongside comments; no new counter category or schema migration is required and issue-creation receipts remain separate. No write, stored rendering, audit event, HTML, receipt or side effect; no automatic request on keystrokes. Archived/private/forbidden and malformed content fail closed.
- `GET /api/v1/projects/:projectId/audit?limit=20&after=...`: bearer-only, current project Administrator, existing `audit:read` permission and existing bounded `AuditRepository`/`createAuditService.read`. The established project-bound cursor, strict ordering, closed/redacted audit catalog and before/after authorization checks remain authoritative. The HTTP DTO omits metadata and request IDs; it includes only identifiers, action/result/time needed for browsing. A query cannot read deployment-wide events or another project. No edit/delete operation or persistent schema change.

Upload transport adds optional public `uploadOrigins` (at most 16 distinct exact HTTPS origins, loopback HTTP only in local development). CSP `connect-src` receives these exact origins and the existing configured isolated media origins. Only approved capability destinations receive file bytes; access tokens never go to storage. No wildcard, arbitrary runtime script, changed sanitizer, HTML sink, credential persistence or weakened Core permission is introduced. Capability URLs stay in memory. External images use explicit isolated navigation to preserve the existing exact-origin image CSP.

Local HTTP/browser verification and the [focused implementing-agent review](12-focused-review.md) are recorded separately; this document defines the bounded design, not hosted acceptance. Context7 Elysia and Playwright resolve/query and the current forms/validation/IME guides were retrieved on 2026-10-18. Pinned installed types and runtime checks supply version-specific integration evidence.

## First-party assurance recovery prerequisite

Browser QA confirmed the existing sensitive-action policy rejects password assurance 1. [ADR 0016](../../decisions/0016-first-party-passkey-step-up-controls.md) records the authorization-origin controls that use existing native passkey registration/login and PKCE consent. The fixed first-party browser asset is outside the business API inventory. Only instances with configured passkeys receive its exact self script/connect permissions; unsupported deployments retain their existing script-free page behavior. Browser verification and focused review pass their recorded local scopes; see ADR 0016 and the linked acceptance records.

The explicit preview request also accepts `{formId,formVersion,values}`. It loads the current enabled immutable form, rejects stale versions, validates/normalizes answers through the same application service as submission and derives its deterministic Markdown through the central policy. It neither consumes attachments nor grants media access. The optional media header `x-hyperbug-preview-type` is limited to released PNG/JPEG/GIF/WebP; downloads still force `application/octet-stream` and attachment disposition. CSP exposes only configured exact storage/media origins; upload transport additionally rejects the SPA/API/auth origins so same-origin cookie behavior cannot send credentials to a file capability.
