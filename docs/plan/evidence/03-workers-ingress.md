# Phase 03 signed Workers ingress checkpoint

Date: 2026-09-27. Scope: partial 03.3c–03.3f and 03.V2–03.V3. This is local route/runtime evidence; deployed ingress, provider and multi-location acceptance remain open.

## Boundary and behavior

The public `apps/api-cloudflare/src/ingress.ts` Worker calls the API Worker through a same-account service binding. Staging and production API configurations disable `workers.dev` and preview URLs, with no public route declared. Both Workers receive the same 256-bit `HYPERBUG_INGRESS_KEY` as a secret. The gateway rejects a missing/malformed client IP, requests carrying `x-real-ip` or `cf-worker`, and Cloudflare's documented cross-zone Worker IP. Its early 503 responses are no-store with `nosniff`. It removes ordinary client-address/forwarding headers and replaces incoming `x-hyperbug-ingress-*` headers with an HMAC-SHA256 assertion over version, method, exact path/query, canonical IP and issuance time. The API verifies the signature and a five-second age bound before supplying the IP dimension to root-bound sensitive admission. Missing/malformed/expired assertions return 503 before approximate or primary counter writes. No key is configured in the ordinary local API environment, so direct local requests remain closed. The gateway forwards the request body through the service binding without exposing the assertion in a response.

This boundary requires the public API hostname to route **only** to the controlled gateway, the API Worker to remain private, and no untrusted same-zone Worker code to invoke the gateway with a manipulated `x-real-ip`. Cloudflare's [address-header reference](https://developers.cloudflare.com/fundamentals/reference/http-headers/) says a same-zone Worker can alter the value used for `CF-Connecting-IP`; rejecting visible subrequest headers is defense in depth, not proof that every such subrequest is distinguishable. Actual zone/routing behavior and attempts from another Worker in the target account must be checked before treating the gateway's IP as deployed trusted provenance. A cross-zone Worker address is rejected. The shared HMAC prevents a direct caller from inventing an IP assertion to the private API Worker. The key must be provisioned separately to both Workers and rotated together; absence or malformed material keeps the route closed.
