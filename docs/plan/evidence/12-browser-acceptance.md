## Corrections discovered by this batch

- Simultaneous editors and repeated command forms needed generated IDs rather than shared IDs or labels containing spaces.
- Pending/ambiguous submissions now lock their value snapshot so retry cannot silently change a committed payload's receipt.
- Issue/comment edits refetch before opening and support explicit discard/reload with a new revision baseline. Stale Issue Forms have an explicit discard/reload control.
- Unavailable upload fields retain a named focusable group for validation instead of an orphan label.
- The plugin configuration API returns stored rows only. Controls now originate from validated manifest declarations so unset settings can be configured; only public scalar defaults and secret presence are merged from reads. Secret plaintext/defaults never enter display state and successful secret writes clear their inputs.
- Worker secret-write fixtures needed the existing envelope-KEK registry entry. Its absence correctly returned a closed unavailable response; seeding the disposable registry fixes the fixture without changing production key policy.
- First-party authorization sessions and app bearer tokens use separate revocation paths under the existing contract. The account page and bilingual guide explain this. The draft-failure test explicitly revokes the bearer; the account-control test separately revokes an authorization session, verifies remaining app access, then signs the app out.
