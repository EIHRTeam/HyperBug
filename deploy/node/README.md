# Self-hosted deployment inputs

Use Node 24, PostgreSQL 18.x and the frozen workspace. `public-policy.example.json` passes the application's public policy parsers; it contains no credentials and is not an environment loader. `node tooling/check-deployment.ts node deploy/node/public-policy.example.json` checks it offline. Inject its settings through your process manager, and replace example domains before use.

Run `node tooling/provision-operator-files.ts /absolute/new/private/directory` offline. It creates independently random key, abuse, bootstrap and ingress material with exclusive mode-0600 writes in a mode-0700 directory, prints no values and refuses existing directories. Mount keys as `HYPERBUG_KEY_FILE`, abuse as `HYPERBUG_ABUSE_KEY_FILE`, and initial enrollment as `HYPERBUG_BOOTSTRAP_FILE`. Generation does not activate keys: use the audited registry integration described in `docs/OPERATIONS.md`. Store required historical key versions separately from ordinary backups.

Configure either `HYPERBUG_DATABASE_URL` (verified TLS outside explicit local loopback) or absolute `HYPERBUG_DATABASE_SOCKET_DIR` with `HYPERBUG_DATABASE_NAME`/`HYPERBUG_DATABASE_USER`. Use a migration-owner connection separately as `HYPERBUG_MIGRATION_DATABASE_URL`; never put credentials into command arguments. The current combined API/Graphile process runs Graphile schema migrations itself; do not claim a separately verified least-privilege worker role or an independent worker-only CLI.

Apply schema with `node tooling/migrate-postgres.ts --status`, then `--apply`. Build with `corepack pnpm build`; run `node dist/node/index.mjs` from the repository root with its pinned workspace dependencies and Wasm/assets intact. The root build layout is checked by the release evidence; do not ship just one JS file. Configure `PORT`/`HOST` explicitly and bind loopback behind a verified HTTPS boundary, or select the existing private `HYPERBUG_TLS_FILE` native TLS configuration. Remote media requires native Node TLS in the current root even when a reverse proxy is present.

Optional `HYPERBUG_UPLOAD_STORAGE_FILE` uses a private owned file containing endpoint/bucket/region/forcePathStyle/credentials. HTTPS is required outside explicit local loopback. S3 compatibility is provider/version-specific; see the reader provider matrix. Set isolated `HYPERBUG_MEDIA_ORIGIN`; configure exact bucket CORS and scanner separately before releasing attachments.

Supervise the combined process with restart and a finite shutdown budget chosen from your measured workload. SIGTERM/SIGINT close uploads, HTTP, active dispatch, Graphile runner/utilities and pool; let the process drain before force-killing. Reconciliation recovers durable pending work after a crash. No systemd/container/reverse-proxy deployment is certified by local macOS checks. Verify certificate/hostname/HSTS, inaccessible direct HTTP, client-IP provenance (Node ignores arbitrary forwarding headers), body limits and timeout behavior at the selected terminator before rollout.
